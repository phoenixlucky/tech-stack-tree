ASSEMBLY PIPELINE · 装配管线

从磁盘配置到一次模型请求

扩展不是启动时静态拼好的。配置、注册表与上下文在每个会话、每个模型步骤持续重算。

  1. 01

    合并配置

    Managed → System → Console → Global → Project → .opencode，JSONC 支持变量替换。

  2. 02

    发现扩展

    扫描全局与项目目录，加载 Markdown、JSON、本地包与远程协议目录。

  3. 03

    建立注册表

    同名后者覆盖；插件变换叠加；策略与权限先做过滤与收窄。

  4. 04

    组装上下文

    固定顺序拼接系统提示、项目指令、技能目录与按需发现的嵌套规则。

  5. 05

    锁定快照

    模型 + 工具定义 + 权限规则形成快照，工具执行前再做一次授权判定。

GUARDRAILS · 权限与策略

两套规则，两个方向

Permissions 面向 Agent 的工具使用，可以询问；Policies 面向组织与机器边界，只收紧、不弹窗。

PERMISSIONS

可交互的工具规则

每条规则由 action、resource、effect 组成，后匹配者胜出；无匹配时默认询问。

  • allow 直接执行，ask 等待客户端决定，deny 阻止并让模型看到原因。
  • 全局规则先加载，Agent 规则追加在后，因此可以精确收窄而不覆盖全局。
  • 批准选项：仅一次、始终允许并保存项目级规则、拒绝；保存的规则不能覆盖配置的 deny。
  • Shell 先经过命令扫描器拆分与推断；补丁涉及多个路径时，任一 deny 即整体拒绝。
  • 子代理使用自己的权限，不是父代理权限的子集；子会话创建时继承当时的会话规则。
// 先宽后窄，最后匹配者生效
{ "permissions": [
  { "action": "shell", "resource": "*", "effect": "ask" },
  { "action": "shell", "resource": "git status *", "effect": "allow" },
  { "action": "edit", "resource": "*.env", "effect": "deny" }
] }
POLICIES

不可绕过的硬边界

策略语句是二元的：只允许 allow 或 deny，永不询问，且只会在权限与 Provider 判断之后进一步收紧。

  • 动作覆盖 provider.use、tool.use、mcp.use、skill.use、plugin.use、websearch.use 与集成连接。
  • tool.use 的资源形如 shell:git push *，在 Agent 规则和“始终允许”之后执行，因此能压过已保存的批准。
  • 优先级方向与普通配置相反：托管配置、系统配置、Console 工作区高于用户与项目。
  • 仓库无法用本地 allow 重新打开组织级 deny；被拒绝的 MCP、Skill 或 Plugin 直接移除或不再加载。
  • 策略不提供插件沙箱，也不配置端点或凭据；它只回答“能不能用”。
// 组织边界：全局拒绝，仅放行指定来源
{ "policies": [
  { "action": "provider.use", "resource": "*", "effect": "deny" },
  { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  { "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }
] }

CLIENTS & CLI · 入口

同一个服务，六种进入方式

TUI、桌面端、Web、API、ACP 与 SDK 共享后台服务；CLI 既启动界面，也管理扩展与生命周期。

TERMINAL

TUI 与命令行

默认进入全屏终端；也可以只跑一次提示，或作为 ACP Agent 被编辑器启动。

  • opencode
  • opencode mini
  • opencode run
  • opencode acp
  • --standalone
  • --server <url>
默认发现或启动一个共享后台服务；--standalone 使用私有服务。
DESKTOP & WEB

桌面端与 Web UI

桌面窗口加载 GUI 插件；Web UI 由同一服务提供，通过一次性链接配对并受密码保护。

  • opencode pair
  • opencode serve
  • Desktop GUI
  • GUI plugin
  • 30 天会话
  • 远程隧道
服务默认只监听 localhost；远程访问需显式开启并仍要求服务密码。
API & SDK

HTTP API 与嵌入

服务端暴露 OpenAPI；客户端库、进程内 SDK 与插件上下文共享同一套资源模型。

  • /openapi.json
  • opencode api
  • @opencode/client
  • @opencode/client/effect
  • SDK
  • ctx.* plugin client
会话、消息、权限、MCP、Skill、Tool 都有对应 API 与事件流。
MANAGEMENT CLI

扩展与服务管理

用 CLI 管理 MCP、插件、后台服务和登录，避免手写配置时破坏无关字段。

  • opencode mcp add | list | auth | logout
  • opencode plugin add | list | check | update | remove
  • opencode service set | start | status | restart
  • opencode auth login
  • opencode debug paths
  • opencode uninstall
配置变更通常自动热重载；被禁用的共享服务仍可用 --server 显式连接。
CODE MODE

REQUEST LIFECYCLE · 请求生命周期

一次输入如何走完全程

每一步都可能被插件、权限或策略改变；模型只看到最终装配出的快照。

  1. 01

    进入

    TUI、桌面端、Web、API 或 ACP 提交提示，服务端确定目录、Agent 与会话。

  2. 02

    准入

    prompt 钩子可脱敏、补附件、选择 Skill；随后附件与 Skill 引用被解析。

  3. 03

    装配

    系统提示、项目指令、引用、MCP 指引、日期环境与会话条目按固定顺序拼接。

  4. 04

    推理

    context 钩子修改请求；Provider / Model 解析后流式调用，失败则按策略重试。

  5. 05

    选工具

    模型选择内置工具、MCP 工具、插件工具或 execute 脚本；工具定义来自本轮快照。

  6. 06

    授权

    Action / Resource 匹配 Agent 规则与已保存批准，再由 Policy 做最终硬拒绝。

  7. 07

    执行

    工具在权限范围内运行，回报进度、取消信号与截断后的结果；完整输出可落盘。

  8. 08

    收尾

    结果回填后进入下一步；接近预算时压缩，快照支持撤销，子代理异步回报。

COMPARISON · 选型对照

该用哪一种扩展

先判断“要接系统、教方法、改运行时、换角色还是固化入口”，再选择载体与治理方式。

扩展类型 载体 何时进入上下文 执行位置 治理动作 最适合
MCP协议化外部能力 本地命令 / 远程 URL 连接后注册工具；工具描述进入清单 独立 server 进程或远端 <server>_<tool>、mcp.use 接 SaaS、数据库、浏览器与团队内部系统
Skill任务知识包 SKILL.md + 支持文件 仅摘要常驻；命中后加载正文 不执行，改变 Agent 行为 skill、skill.use 团队流程、发布规范、领域知识与检查清单
Plugin代码级扩展 npm / git / 本地目录 启动或热重载时注册，可拦截每次请求 Server 同进程；TUI / GUI 各自进程 plugin.use、可信来源 自定义工具、审计、脱敏、模型路由与界面面板
Agent角色与委派 agents/*.md 或 JSON 会话选定或子代理启动时 主会话或独立子会话 subagent、Agent 自身权限 只读审查、规划、并行调研与专模专用
Command提示入口 commands/*.md 或 JSON 用户输入 /name 时展开 当前会话或指定子会话 目标 Agent 的权限 周报、评审、发布、审计等固定任务
Tool原生动作 内置实现 / 插件注册 每轮以工具定义进入请求 Agent 进程内或受控运行时 按 action 匹配资源 文件、命令、网络、提问与脚本编排
Instruction长期规则 AGENTS.md / instructions 会话开始与探索目录时注入 仅提示，不执行 无独立权限；受上下文预算约束 构建命令、代码约定与验证要求
Reference外部目录 本地路径 / Git 仓库 客户端附带别名时 只读缓存检出 external_directory 等常规规则 文档站、共享库、跨仓库源码

CROSS-CUTTING · 设计取舍

六个贯穿所有扩展的约束

扩展点越多，越需要把上下文、信任、重载与可复现性当作一等约束。

CTX

上下文预算

能晚加载的就晚加载，能截断的就截断；把最贵的上下文留给当前步骤。

TRUST

信任边界

协议数据不等于指令；插件是代码；shell 继承宿主用户权限。

HOT

热重载

改配置不重启；本地未监视依赖与已捕获的注册变换需要显式 reload。

REPRO

可复现

锁版本、留快照、用工作树隔离并行任务，避免“只在我机器上能跑”。

CONC

并行与隔离

子会话、后台任务与脚本并行，减少等待，也避免中间结果污染主上下文。

OBS

可观测性

记录模型、工具、权限与压缩事件；失败时先定位是服务、项目还是单次请求。
