PROTOCOL CORE · 协议内核

无状态请求，双向通知

不是 REST 资源树，也不是带会话状态的 RPC：请求由 Client 发往 Server，响应回到 Client，通知双向流动；每条请求自带版本与能力。

WIRE

消息只有三种

请求带 id，响应按 id 配对，通知没有 id 且不需要回复。每个请求的 _meta 自带协议版本与客户端能力。

// 请求 · 客户端发起，自带上下文
{ "jsonrpc": "2.0", "id": 42,
  "method": "tools/call",
  "params": {
    "name": "crm_lookup",
    "arguments": { "email": "a@b.c" },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    } } }

// 响应 · resultType 表示结果类型
{ "jsonrpc": "2.0", "id": 42,
  "result": {
    "resultType": "complete",
    "content": [...], "isError": false } }

// 通知 · 不要回复
{ "jsonrpc": "2.0",
  "method": "notifications/subscriptions/acknowledged" }

方法名按 domain/action 组织：tools/list、tools/call、resources/read、prompts/get。

STATELESS

先发现，再按请求声明

server/discover 是服务端必须实现的能力发现入口；客户端可选地提前拿到版本、能力与 instructions。之后的每个请求仍要自带 _meta，不能依赖连接上的前置状态。

  1. server/discover客户端可选调用；返回支持的版本、能力、instructions
  2. request + _meta每请求携带 protocolVersion 与 clientCapabilities
  3. list / get / read建立工具、资源与提示目录
  4. call / progress / cancel执行、进度、取消与超时
  5. input_required服务端请求补充输入，例如 elicitation
  6. subscriptions/listen订阅目录或资源通知；连接不是会话
stdio 本机子进程 Streamable HTTP 远程 HTTP + SSE 兼容

stdio 用 stdin / stdout 传消息，stderr 留给日志；HTTP 使用 POST 与可选的事件流，并校验 Origin。

COLLABORATION · 协作面

把 Server 当成另一个 Agent

工具只回答“能做什么”。生产环境还要回答“怎么做、做多久、做到一半找谁确认、文件怎么给”。这不是让 server 变成 Agent，而是补齐 Agent 间协作的接口——Skills、Tasks、Elicitation 与 File Uploads 把这四件事补上。

  • 最佳实践
  • 工作流
  • playbook

可执行动作、副作用与外部系统调用；输入由 schema 定义，结果回到 Agent。

  • 查询
  • 写入
  • 调用

CONTEXT

  • 文档
  • 记录
  • 附件

三层是能力供给，四种动作是协作方式：学方法、派长活、问用户、换文件。

SKILLS

渐进披露

skills/list 发现，skills/get 取元数据，resources/read 读 SKILL.md 与配套文件；先看摘要，再按任务加载正文。

扩展标识：io.modelcontextprotocol/skills · 建议上限 512 文件 / 16 MiB

Host 校验 manifest、SHA-256 与 frontmatter；文件变更会撤销批准。与本地 Skill 的差别在分发与维护：来源、更新、工具关联、个性化与安装都随 server 走。

TASKS

持久句柄

Server 返回 resultType: task 与 taskId；用 tasks/get 轮询，tasks/update 补输入，tasks/cancel 请求取消。

状态：working · input_required · completed · failed · cancelled；也可订阅 notifications/tasks。断连可恢复，取消是协作式；适合 Deep Research、CI/CD、批处理与多 Agent 并行。

ELICITATION

多轮往返

Server 返回 input_required，Client 用表单或链接收集输入，再带着输入重发原请求；它是交互机制，不是完整安全系统。

FILE UPLOADS

原始文件

PDF / Excel / 图片直接传给 server，不经过上下文窗口；专业引擎处理后返回结构化结果，减少 token 与序列化损耗。

不经过上下文不等于绕过审查：类型、大小、来源与恶意内容仍需校验。

BETA / GA / ROLLING OUT 为 Claude 产品状态（2026-11），不等同于协议扩展阶段：Tasks 扩展 Beta、目标 Core，MCP Apps Stable，File Uploads Experimental。

CONTEXT ECONOMICS · 上下文经济学

把工具变成代码，而不是把工具塞满上下文

Code Mode 不是 MCP 协议的一部分，而是 Host 侧对工具的一种装配方式。Anthropic 工程团队给出的同一任务对照：150,000 tokens 的工具上下文，按需读取后约 2,000 tokens，节省 98.7%。关键不是换模型，而是换调用方式。

tools→files→code→filter→answer

DIRECT TOOL CALLS 所有工具定义常驻上下文
≈ 150,000 tokens
CODE MODE 列目录，只打开当前需要的 2 个文件
≈ 2,000 tokens
−98.7%

示例来自 Anthropic《Code execution with MCP》（2025-11-04）：同一批工具、同一任务，只改变工具呈现方式与结果回传路径。

01

工具即文件

每个 MCP 工具变成一个 .ts 文件，按 server 分目录；模型先看目录，再打开需要的接口。

servers/
├── google-drive/
│   ├── getDocument.ts
│   └── index.ts
└── salesforce/
    └── updateRecord.ts
02

按需加载

先列 server，再读工具文件；也可以提供 search_tools，按名称、摘要、完整 schema 分级返回。

150k → 2k 打开 2 个文件 98.7% 节省
03

在代码里过滤

10,000 行表格在沙箱里筛选，模型只看到 5 行；大文档、join 和聚合都不必穿过上下文。

const rows = await gdrive.getSheet({ sheetId });
const pending = rows.filter(r => r.Status === 'pending');
console.log(pending.slice(0, 5));
04

在代码里循环

等部署完成、轮询 Slack、重试失败请求，都在一次脚本里完成，不再每一步都回到模型。

while (!found) {
  const msgs = await slack.history({ channel });
  found = msgs.some(m => m.text.includes('deploy complete'));
  if (!found) await sleep(5000);
}
05

默认私有

中间结果留在沙箱；邮箱、电话等字段先变成 [EMAIL_1]、[PHONE_1]，真实数据仍写入目标系统。

[EMAIL_1] [PHONE_1] [NAME_1]
06

沉淀为 Skill

验证过的脚本存进 ./skills，补一个 SKILL.md，下次直接复用，而不是重新推导。

skills/
└── save-sheet-as-csv/
    ├── SKILL.md
    └── save-sheet-as-csv.ts

ASSEMBLY PIPELINE · 装配管线

从一个 server URL 到一次可用调用

连接不是配置文件的附属品，而是一条有发现、目录、授权、快照和执行的生命周期。

  1. 01

    配置

    声明 command 或 URL、超时与版本策略；凭据不写进普通配置。

  2. 02

    发现

    server/discover 预取版本与能力；每请求再带 _meta。

  3. 03

    建目录

    拉取工具、资源、提示与 skills，用 subscriptions/listen 订阅变更。

  4. 04

    归一

    统一命名为 <server>_<tool>，或生成 Code Mode 文件树。

  5. 05

    授权

    OAuth + PKCE、绑定 audience、逐 server / 逐工具授权；企业可托管认证。

  6. 06

    快照

    模型、工具、Skill 摘要与权限规则冻结在这一轮请求里。

  7. 07

    执行

    短调用直接执行；长任务交给 Tasks，文件走 File Uploads，必要时补输入。

  8. 08

    审计

    记录调用、任务句柄、文件引用、结果状态与错误，支持回放。

FAILURE MODES · 失败模式

MCP 架构最容易坏在哪里

协议解决“怎么连”，不自动解决“连多少、信多少、传多少”。下面这些问题通常成对出现。

GUARDRAILS · 三层护栏

协议、执行、上下文，各管一段

授权解决“谁能用”，沙箱解决“能碰什么”，上下文策略解决“模型能看到多少”。三者不能互相替代。

PROTOCOL

协议护栏

  • 远程连接使用 TLS；stdio 只启动可信的本地命令。
  • OAuth 2.1 + PKCE；按 RFC 8707 绑定 resource / audience，禁止透传。
  • 逐 server 授权与登出；HTTP 校验 Origin，令牌绑定用户；企业可用 Managed Auth。
  • 只使用请求中声明且服务端返回的能力；版本不兼容即拒绝。
  • 远程 Skill 视为不可信指令：校验来源、manifest、SHA-256 与版本；文件变更重新批准，跨 server 读取需显式同意，且不得扩大工具权限。
EXECUTION

执行护栏

  • Code Mode 在沙箱或隔离运行时执行，限制 CPU、内存与时长。
  • 文件访问走显式目录授权或沙箱边界；File Uploads 校验类型、大小与来源。
  • 网络出口按域名 / 端口白名单；敏感动作与写操作要求人工确认。
  • 记录工具来源、任务句柄、文件引用、结果状态与失败原因。
  • Elicitation 不是完整安全系统：仍要权限校验、身份认证、审批规则与审计。
CONTEXT

上下文护栏

  • 工具定义、Skill 与文件都按需加载；优先给目录、摘要与引用。
  • 结果先过滤、聚合、截断；完整内容落盘并给引用。
  • PII 在进入模型前 token 化，在 MCP 边界再还原。
  • 每轮锁定模型与工具快照，逼近预算时压缩或分派子会话。

Function Calling模型动作 模型调用函数的机制 如何执行一次操作 只管一次调用，不负责编排
MCP连接协议 标准化连接协议 如何连接外部能力 协议本身不提供业务方法
Skill专业方法 可复用的专业工作方法 如何正确完成工作 加载后不会自动变成 Agent
Agent自主系统 具备规划与执行能力的系统 如何自主完成目标 可以调用 MCP，但不等于 MCP
A2AAgent 协作 Agent 间协作协议 独立 Agent 如何相互协作 与 MCP 的抽象层次不同
RAG知识检索 外部知识检索增强 如何获取相关知识 解决知识，不解决动作
Workflow流程编排 工作流程编排 如何组织执行步骤 确定性编排，不替代自主规划

Skill ≠ Agent：Skill 是指令、知识与资源，被加载后不会自动成为独立运行的 Agent；支持 Tasks 的 MCP Server 可以在自己的环境中执行完整 Agent Loop，但并非每个 Server 都是 Agent。

如果是 Server 设计者，按七个维度检查：

Knowledge 领域知识与业务规范 Skills 标准流程与决策指南 Tools 原子操作与业务动作 Resources 业务数据与参考资料 Tasks 持久、可恢复的长任务 Elicitation 用户审批与补充信息 Security 权限、验证与审计

不是每个 server 都要实现全部维度：简单查询服务可能只需要 Tools / Resources；复杂企业平台才需要完整的任务编排与交互机制。

DESIGN CHECKLIST · 落地清单

接入下一个 MCP Server 前

六个问题回答清楚，架构基本就稳了；回答不清，通常会在上下文或权限上付出代价。

01

边界是否单一

一个 server 对应一个系统，工具命名与返回结构稳定。

02

默认是否按需

工具、Skill 与文件按需加载，而不是启动时全量注入。

03

结果是否有上限

结果截断、分页、落盘；文件不要塞进上下文。

04

令牌是否绑定

audience、scope、过期时间与登出路径都可验证。

05

调用是否可审计

调用、任务句柄、文件引用、状态与拒绝原因都能回放。

06

是否可替换

版本锁定、契约测试、降级路径与离线兜底。
